## PETSc：谱消去并非任意正交压缩

实际 `PCPreSolve_Deflation` 形成 `r=b−Ax`，然后用粗求解增加校正。常规说明中的 `Q=W(W*AW)⁻¹W*` 与 `P=I−QA` 进入预条件器，不能仅因为使用了 projection 一词，就把它们认作 F300 的自伴正交投影 `q`。对一般 A，W 满列秩本身也不是粗矩阵可逆的充分证书。代码有初值校正、额外预条件器和多层粗求解的实际成本，不能只计最终块数。

所选 `ex11.c` 全部244行已读：它构造复数 Helmholtz 五点差分，带虚对角项；设置 A 同时作为系统与预条件矩阵，求完整 `Ax=b`，对已知解 u 计算 `‖x−u‖₂`。实际 deflation 测试配置要求复数构建及 SuperLU_DIST。通用实现存在 SPD 分支，不把这个具体调用变成自伴正定问题。这里没有允许忽略某个子空间的状态预算。说明中的初值符号与实际残差约定不据此宣称外部软件有错误。

## Ginkgo：块大小、逆块和实际残差

Jacobi API 接受连续行列区间的起点，或者运行启发式块检测；生成阶段处理排序 CSR、对角求逆或块生成，应用阶段调用存储的逆块。API 的默认最大块是32，参数说明及实际 executor stride 还区分 NVIDIA／AMD，不能由概览的一句32推断所有平台的绝对上限。后端 kernel 正文和性能未核查。

自适应存储用于降低部分逆块的精度。API 对 accuracy、off-diagonal dropout 及问题相关常数的描述，不是 F300 给出的统一算子范数定理。实际94行求解示例采用 double、最大块8、CG至多20次及残差缩减参数 `1e−7`，最终打印完整 `‖Ax−b‖₂`；没有启用自适应精度。示例引用的 A／b／x0 数据文件没有获取，不能据 CG 名称宣布这些具体输入已被验证为 SPD 或具有某个条件数。

即使某个铺砌分割在数学上存在，还要计算重排序、最大块大小、逆块和条件数、存储格式、预处理成本、迭代次数及完整残差。少块不等于小块；压缩剩余误差也不直接给出逆块精度或求解器加速。

## TeNPy：确有状态损失消费者，但保留结构不可省略

`svd_theta` 实际做 SVD，先归一化 Schmidt 谱，再选择保留掩码，裁剪 U／V 并返回归一化因子。`TruncationError.eps` 记录被丢弃 Schmidt 值平方之和；`ov` 与累计 `eps` 是不同字段。`trunc_cut` 对应平方阈值，而且约束按次序组合：后来的约束若与前面的允许集合无交集，`_combine_constraints` 发出警告并保留前面的集合。因此不能承诺每个配置阈值都无条件满足。

TEBD 的实际两点更新要从这些因子重建带标签的局部张量、Schmidt 键和正则形式，并累计键上的截断误差。它是真实的状态损失消费路径。可是 F300 的一般 `q` 未提供同样的局部因子、键秩预算和荷兼容证书，也未证明可以省去现有 SVD 或降低完整成本。状态权重与强拓扑条件的具体对应、支撑／忠实性条件及物理误差还需分别确认。

这里还必须区分父类与实际调用：`TimeEvolutionAlgorithm.evolve` 中有对 `max_trunc_err`、默认0.01的检查调用；所选 `TEBDEngine.evolve` 重写了方法，没有调用该父类循环。实际 TEBD 的 `calc_U` 检查的是时间步 `max_delta_t`。不能把父类文档当作 TEBD 已执行0.01截断闸门的证据。父类与子类各自累计计数的静态路径已保留，运行期误差记账并未独立验证，不提出外部缺陷或性能结论。

虚时间求基态使用能量变化作为停止量。截断误差不等于基态保真度，时间离散的 Trotter 误差也仍在。这些边界来自选定源码及模块说明，没有运行新的数值实验。
